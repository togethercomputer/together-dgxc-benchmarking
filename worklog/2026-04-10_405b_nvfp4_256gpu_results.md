## Key Findings

1. **PP=16 → PP=8 delivers +38% throughput** — the single largest optimization. Halving pipeline depth reduces P2P comm by 84% and bubble fraction from 43% to 15.5%.

2. **DP doubles from 4 to 8** — with TP=4 and PP=8, DP = 256/(4*8*1) = 8. More data parallelism provides better gradient averaging overlap.

3. **TP=8 is not viable on this cluster** — Config C hung during NCCL communicator init. TP=4 is the correct choice for B200 nodes.

4. **VP=4 is optimal for PP=8** — VP=8 adds marginal overhead (-0.7%) without improving pipeline interleaving. VP=4 provides sufficient virtual stages.

5. **CP=2 is a regression (-44%)** — context parallelism halves DP (8→4) and adds communication overhead that doesn't pay off at seq_length=8192. CP is better suited for very long sequences.

6. **SHARP is not available** — NCCL_COLLNET_ENABLE=1 causes hangs; SHARP AM has no reservations for training jobs on this cluster.

7. **Communication-compute overlap is effective** — ~26.6s of comm hidden behind compute per step. overlap_grad_reduce and overlap_param_gather are working.

8. **aten::item sync stall: 1.9s/step (2.9%)** — train.py:385 loss_scale.item() forces GPU sync. Worth fixing for a free ~3% gain.

9. **Remaining bottlenecks:** P2P SendRecv (9.1s/step), DP gradient sync (8.6s/step), and 15.5% pipeline bubble are the top three targets.

## Recommendation

**Adopt Config D (TP=4, PP=8, CP=1, VP=4, GBS=1536, DP=8) as the production configuration.**

Training script parameters:

## Further Optimization Opportunities

1. **Fix aten::item stall**: Patch train.py:385 to avoid GPU sync — free ~3% gain (1.9s/step).
2. **Reduce DP gradient sync overhead**: Currently 8.6s/step. Investigate gradient compression or async all-reduce.
3. **Investigate TP=8 hang**: If TP=8 could be made to work, it might enable PP=4 for even less pipeline overhead.
4. **SHARP enablement**: Work with cluster admins to configure SHARP AM reservations — could accelerate all-reduce/reduce-scatter.
5. **Test PP=4 with EP=2**: Expert parallelism as an alternative to reduce pipeline stages further.
6. **Tune recompute_num_layers**: Currently 8. Testing different values could trade memory for compute.
